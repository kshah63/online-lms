VERIFIED PENCIL SPACES API (read directly from api.pencilspaces.com on 2026-10-15; OpenAPI v1.1.0; merged spec saved locally). Everything below is FACT, not assumption. Updated 2026-10-16 with Pencil support's answers to our questions (verbatim in vendor-answers-2026-10-16.md); where support corrects the spec or the helpdesk, the support answer is stated and marked "(support 2026-10-16)".

Base URLs: production https://apis.pencilapp.com/public/api/ ; staging https://staging-apis.pencilapp.com/public/api/ (staging app at https://staging.pencilapp.com, production app at https://my.pencilapp.com). Auth: `Authorization: Bearer <API key>` (Institution Admin generates it in Spaces Manager > Settings > API Key; view-once; revoking or regenerating it signs that account out everywhere (support 2026-10-16)). Rate limit: keep < 5 QPS; 429 on excess; analytics endpoints are slower/stricter. Errors: {err, error_code}. IDs are 24-hex MongoDB ids. Timestamps RFC3339 with offset.
Vendor best practices: use a generic admin account for the key; Spaces and users are PERSISTENT (reuse a Space across a semester; do not create per lesson); subscribe to https://pencilspaces.statuspage.io/.

USERS
- POST /users/createAPIUser  body {name, userRole: 'Student'|'Teacher' (also InstitutionAdmin|SiteAdmin but not creatable via API), externalId?, siteIds?, customAttributes?, languageCode?} -> {userId, email (a Pencil-generated address), name, isApiManaged, userRole, externalId, ...}. externalId = our profiles.id is the intended mapping.
- GET /users/{userId}/authorize?redirectUrl=<url-encoded FULL Space URL incl. params> -> {url}. Token valid 3600 s. If the user is already logged in to Pencil in that browser they are logged out and re-logged as this user. Alternative form: https://my.pencilapp.com/spaces/{spaceId}?loginMethod=token&loginType=api&token={token}.
- GET /users (filters: query, roles, sites, customAttributes; paginated), GET /users/{userId}, PATCH /users/{userId} {name, externalId, siteIds, customAttributes, languageCode}, DELETE /users/{userId}/remove (PERMANENT: API users cannot be re-added), POST /users/inviteUser (email-based, not for us).

SPACES
- POST /spaces/create body {title?, spaceToCloneId? (template Space), owner? {userId|email} (defaults to API-key user), hosts: [{userId}|{email}], participants: [{userId}|{email}], visibility: 'public'|'private', notifyInvitees (REQUIRED boolean; set false), siteId?, externalId? (must be unique)} -> {spaceId, link (the Space URL), title, visibility, hosts[], participants[], archived, externalId, settings{disableAlwaysOnRecording, enableWaitingRoom}, createdAt, editedAt}. Without `owner`, the API-key user becomes the owner and is added as a host (the spec says "always"; support 2026-10-16: only when `owner` is not set — with `owner` passed, the API account is not added and does not appear in the Space UI, and "Grant admins access to all Spaces" (default ON) must stay on so it can still manage the Space). We do NOT pass `owner` (plan decision p: an owner is recorded as permanent, and teachers must stay removable hosts). Pencil institution admins reach every Space through "Grant admins access to all Spaces" (default ON) without being members; our own admins are API 'Teacher' users and are seated as hosts explicitly.
- GET /spaces (filters: query, hosts, participants, owner, externalId, archiveStatus, customAttributes, createdRange; paginated, pageSize max noted) -> {results[], pageNumber, pageSize, totalPages, totalRecords}. externalId filter lets us look up "our" Space idempotently.
- GET /spaces/{spaceId}; PATCH /spaces/{spaceId} {space:{title, visibility, archived}}; DELETE /spaces/{spaceId}.
- PATCH /spaces/{spaceId}/updateUsers {addUsers:[{userId|email, role:'host'|'participant'}], modifyUsers:[same], removeUsers:[{userId|email}], notifyInvitees (default true; set false)} -> space. Every Space needs >= 1 host; cannot remove/downgrade the API-key user. USE THIS for teacher reassignment.
- PATCH /spaces/{spaceId}/settings/ {settings:{disableAlwaysOnRecording?, enableWaitingRoom?}} -> {}. disableAlwaysOnRecording only matters if always-on recording is enabled at institution level. It takes effect from the NEXT call and does not stop a recording that is already running (support 2026-10-16). No endpoint returns the effective recording state: `settings.disableAlwaysOnRecording` is the stored setting, a recording in progress is not listed until it finishes, and RECORDING_AVAILABLE is the signal that one was made.
- POST /spaces/{spaceId}/endOngoingSession -> {endedSessionId, newSessionId|null}. Ends ONLY the analytics session and immediately starts a new one for anyone still in the Space; it does NOT end the call, disconnect participants, or stop or split the cloud recording (support 2026-10-16). Pencil itself ends a session six minutes after the last participant leaves or becomes inactive, so support sees no need to call it. WE DO NOT CALL IT: "End lesson" unmounts every room instead (plan decision b).
- Space URL params (append to the Space link that goes in redirectUrl): startCall=true (auto-start call when a host joins), skipCallHostCheck=true (with startCall: auto-start for participants too — support 2026-10-16: `startCall=true&skipCallHostCheck=true` lets a PARTICIPANT start a call alone, and under always-on recording that call is recorded and Cloud Recording is billed while it records), skipDeviceSetup=true (skip join modal; joins muted/camera off), gv=true (gallery view), standalone=true (hide Spaces Manager nav, Copy Link, Invite — it only hides navigation and does not change who can start a call), mode=whiteboardonly (support 2026-10-16: hides the call controls and join prompts on that device; for a second device used to write), language=xx, startLocalRecording=true (local recording; not mobile), broadcastEvents=true (postMessage embed events).
- Who can start a call (support 2026-10-16): by default only hosts. Always-on recording only starts when a call starts, so a user alone on the whiteboard with no call is not recorded.
- Access: private Space = only invited users. Institution setting "Waiting Room" controls whether participants can enter without host approval.

SESSIONS / ANALYTICS (a Session is auto-created whenever >= 1 user is in a Space; it ends six minutes after the last participant leaves or becomes inactive (support 2026-10-16; earlier notes said 5 min); sessions are INDEPENDENT of Events; a session can span rooms)
- GET /analytics/sessions (filters base64-JSON: spaceIds[], createdStart/End, editedStart/End, status 'inprogress'|'processed' (default processed only), callsOnly, billedOnly; paginated).
- GET /analytics/sessions/{sessionId} -> {sessionId, spaceId, sessionTitle, sessionStartTime, sessionEndTime, sessionStats{nActiveUsers, callDuration}, callStats[{callStartTime, callEndTime}], attendees[{userId, email, callActiveTalkingDuration (s), callMicOnDuration, callVideoOnDuration, callCountRaisedHands, callCountReactions, callDuration, callNetworkUnstableDuration, callDeviceStrugglingDuration, callMicErrorDuration, callCameraErrorDuration, callMicErrorTypes[], callCameraErrorTypes[], callBrowserTypes[], callDeviceTypes[], spaceCountPublicMessagesSent, spaceCountPrivateMessagesSent, spaceDuration, spaceDurationInBackground, spaceFirstJoinTime, spaceLastLeaveTime, spaceCountJoined}], roomAttendees[...]}.
- GET /analytics/sessions/{sessionId}/reports -> {coaching: null | {sources[{recordingId, roomId, reportTimestamp, schemaVersion}], score (0-? duration-weighted), categories[{categoryId, name, score, description}], items[{timestamp, recordingOffset (s), recordingId, roomId, itemSeverity, itemType, itemContent{}}]}, safeguarding: null | {schemaVersion, reportTimestamp, items[{source, timestamp, recordingId, recordingTimestamp, roomId, userId, itemSeverity, itemContent}]}}. THIS IS PENCIL'S OWN AI COACHING REPORT. IMPORTANT: "Report data is derived from the session's recordings" — with no cloud recording, coaching AND safeguarding are null.
  Support 2026-10-16: the endpoint answers 200 while processing (never 404), and each block — `coaching`, `summary`, `safeguarding`, `snippets` (the last two blocks are not in the spec) — reflects its own state. `coaching` is null until AI Coach processing starts for the session, and stays null when AI Coach does not apply (e.g. not enabled). Once processing starts it is an object with `status`: `pending` while running, then `completed`, or one of `failed`, `meeting_too_short`, `meeting_irrelevant`, `no_transcript`, `disabled`. Trigger on the COACHING_AVAILABLE webhook (sent only when a report completes WITH insights) and read `coaching.status` when polling to see every other outcome.
- DELETE /analytics/sessions/{sessionId}.
- Billing (support 2026-10-16): on per-user-hour plans Space time is billed only while at least two different users are in the Space, so time alone is not billed and one account on several devices adds nothing; group-session plans bill from the participant threshold (2 users by default). Cloud Recording is billed separately while a recording is active.

RECORDINGS / TRANSCRIPTS (transcripts + summaries are generated for all CLOUD recordings; the docs say recordings are "almost always available within an hour" — support 2026-10-16, as a guide for a one-hour session, scaling with length: recording within a few minutes of the call ending, transcript ~10 min, summary and AI Coach report ~15 min)
- GET /spaces/recordings?startingAfter&endingBefore (paginated) and GET /spaces/recordings/{spaceId}?startingAfter&endingBefore -> {recordings[{spaceId, roomId ('MainRoom' or uuid), recordingId, startingTime, duration (s), fileSize}]}.
- GET /spaces/recordings/download/{recordingId} -> {recordingId, downloadLink (short-lived)}. DELETE /spaces/recordings/{spaceId}/{recordingId}: support 2026-10-16 — the recording disappears for our users from lists and playback, and GET /transcriptions/{recordingId} stops returning it; what else is deleted with it (transcript, summary, AI Coach, safeguarding items) and what Pencil retains is STILL PENDING from Pencil.
- GET /transcriptions/{recordingId} -> {recordingId, recordingStartTime (UTC epoch seconds), transcript: null (legacy) | [] (none) | [{text, start (s from recording start), end (s), userId|null}], transcriptUsers[{userId, email, name, profilePic}], summary: null | {description}}. Diarized by Pencil userId -> map to our teacher/student via profiles.pencil_user_id.
- CONSEQUENCE: our post-session pipeline (transcript, summary, Pencil coaching report) REQUIRES cloud recording to be on for that Space/call. Recording is therefore not optional for lessons that want AI features; it must be gated by the student's 'recording' consent (institution always-on recording + per-Space disableAlwaysOnRecording=true when consent is missing; or host-started recording).

EVENTS / ATTENDANCE (optional for us; our DB stays the schedule of record)
- POST /events {title, description?, start, end (RFC3339 w/ offset), organizers[{userId|email}], attendees[{userId|email}], spaceId (ONLINE events), type 'ONLINE'|'OFFLINE', location?, timezone (IANA)?, siteId?, recurrence{rule RFC5545}?, customAttributes?} -> 201 {event{id, creator, institutionId, title, description, state{status COMPLETED|CANCELLED, note, statusUpdatedBy, statusUpdatedOn}, start, end, organizers[], attendees[], spaceId, recurrence, customAttributes, siteId}}. Organizers get host rights in the Space. Benefits: a SESSION TIMER shows at the top of the Space (host can extend; configurable), attendance is tracked automatically, EVENT_NO_SHOW alerts fire; emails are NOT sent to API-managed users. Constraint: two events cannot run in the same Space at once.
- GET /events?filters=<base64 json>&pageSize&pageNumber, GET /events/{eventId}, PUT /events/{eventId} (full), PATCH /events/{eventId}/update (partial; past/cancelled events: only title/description/customAttributes), DELETE /events/{eventId}, POST /events/{eventId}/cancel {note}, POST /events/{eventId}/rsvp {status YES|NO, user_id, note?}.
- GET /attendance/{event_id} -> {results[{id, email, name, role Attendee|Organizer, status Present|Late|Absent|Left|Excuse, notes, joinTime, autoAdded}]} (past events only). PATCH /attendance/{event_id}/update.
- Availability: GET/POST /availability/slots/{userId} {slots[{day 0-6, start 'HH:MM', end}], timezone} (we do not need this; ours is the source of truth).
- GET /alerts/{id} -> Control Center alert {type TEACHER_DECLINED_EVENT|EVENT_NO_SHOW, status OPEN|ASSIGNED|CLOSED, priority, entityId, triggeredBy, assignedTo, resolution}.

WEBHOOKS (ONE config per institution per environment: a single URL + secret; configure via Settings > API & Integrations > Webhooks or POST /webhooks {url, secret}; GET /webhooks; DELETE /webhooks). Every delivery carries `Authorization: Bearer <secret>`. Payloads (`_type` discriminates):
- SPACE_USER: {spaceId, sessionId, timestamp, eventType: joinSpace|leaveSpace|hideTab|unhideTab, userId, roomId, userTabId, _type:'SPACE_USER'} — support 2026-10-16 names the tab-switch events USER_ENTERED_BACKGROUND and USER_ENTERED_FOREGROUND, so the exact join/leave strings are to be confirmed from the first deliveries (asked).
- SPACE_SESSION: {spaceId, sessionId, timestamp, eventType:'SESSION_ENDED', _type:'SPACE_SESSION'} — fires when analytics processing for the session has COMPLETED (so GET /analytics/sessions/{sessionId} is ready).
- SPACE_RECORDING: {spaceId, recordingId, timestamp, eventType:'RECORDING_AVAILABLE'|'TRANSCRIPT_AVAILABLE', _type:'SPACE_RECORDING'} (TRANSCRIPT_AVAILABLE confirmed by support 2026-10-16; the payload is exactly {_type, eventType, spaceId, recordingId, timestamp}). Webhooks say something is ready and never carry content: fetch it with GET /transcriptions/{recordingId}.
- COACHING_AVAILABLE (support 2026-10-16): Pencil's recommended trigger for the AI Coach report; sent ONLY when a report completes with insights (every other outcome is visible only as `coaching.status`). Its `_type` and fields are not documented yet (asked).
- SCHEDULE: {eventId, timestamp, eventType: EVENT_CREATED|EVENT_UPDATED|EVENT_DELETED|EVENT_CANCELLED, updatedBy, recurringUpdateType?, _type:'SCHEDULE'}
- ATTENDANCE: {eventId, userId, timestamp, updatedBy, prevStatus?{status PRESENT|LATE|ABSENT|EXCUSED, notes?}, currentStatus{...}} (no _type shown)
- PROGRAM_AND_COHORT, CONTROL_CENTER_ALERT {alertId, alertType TEACHER_DECLINED_EVENT|EVENT_NO_SHOW, eventType CREATE_ALERT|UPDATE_ALERT, updatedBy, timestamp}.
- Additional events on request from Pencil support.
- Delivery (support 2026-10-16): a delivery that does not get a 2xx within 15 s is retried with exponential backoff, from 30 s growing to 10 min between attempts, up to 10 attempts in total (if the gaps double, a delivery is abandoned about 55 min after the first attempt). ORDERING IS NOT GUARANTEED, especially across retries. No idempotency key is documented -> we dedupe on (sessionId|recordingId, eventType), answer 2xx for everything stored or ignored, and never assume one event precedes another.

IFRAME EMBEDDING (official guide "Integrating via iFrame"; support 2026-10-16: the Space page sets no frame-ancestors policy and no X-Frame-Options, so embedding from our domain needs nothing on Pencil's side; serve the parent over HTTPS; use the guide's allow list; sign in with token login and generate a FRESH token for every page load, because browser storage partitioning can stop a login carrying over into the iframe; tokens last one hour): two integration modes — Redirect (new tab; simplest, most reliable) or iFrame (branded; "reliability limitations on mobile devices and certain browsers"). iframe must have allow="clipboard-read; clipboard-write; display-capture; fullscreen; autoplay; camera; microphone; picture-in-picture; compute-pressure". Parent page MUST be HTTPS (localhost dev needs a trusted cert) or auth/storage fails with a blank screen. URL params (startCall, standalone, skipDeviceSetup...) must be on the SPACE URL passed as redirectUrl (URL-encoded), not on the token URL. With broadcastEvents=true the iframe posts window.postMessage {type, detail} to the parent (check event.origin in {https://my.pencilapp.com, https://staging.pencilapp.com}): ready, chat_toggle, screenshare_toggle, recording_status_change{status}, participantupdate{count}, participant_join/participant_leave{id (Pencil userId), name, fullName, profileImage}, connection_status_change{Stable|Unstable}, device_performance_status_change, device_status_change{deviceType, state}, user_started_call, user_joined_call, user_left_call, call_ended, user_ended_call, camera_toggle{enabled}, microphone_toggle{enabled}, hand_raised, page_visibility_change{visible}, pip_toggle{open}. => participant_join / user_joined_call replace Daily's peer-joined signal for our lesson clock (actual_start). Standalone mode hides nav/Copy Link/Invite. Branding configurable in settings.

CUSTOM APPS ("Mario" apps): institution-specific embedded apps inside a Space via @pncl/mario client lib (SpaceUsersInfo, synced state, custom events); tested on staging only; published via Pencil review. Not needed for v1; a possible later home for an in-Space materials picker.

DATA MODEL NOTES: Institution > (Sites) > Users (email is the primary key; roles InstitutionAdmin/SiteAdmin/Teacher/Student), Spaces (persistent; rooms inside; permissions: Admin (Pencil institution admins reach every Space via "Grant admins access to all Spaces", default ON, without membership — support 2026-10-16), Owner (creator, or the `owner` passed on create; recorded as permanent by the helpdesk, unconfirmed by support — asked), Hosts, Participants), Sessions (auto, analytics unit), Recordings (per Space+room+time window; may span sessions), Events (scheduled; drive attendance; organizers auto-hosts), Programs/Cohorts (batch scheduling), Custom attributes (tags on users/spaces/events).

ANSWERED BY PENCIL SUPPORT 2026-10-16 (was "still unknown after reading the spec"; detail in vendor-answers-2026-10-16.md): (1) the transcript event is SPACE_RECORDING / TRANSCRIPT_AVAILABLE; (2) there are no live coaching nudges — the only live host alert is the distraction notification (tab switch), not exposed by the API, whose signals are SPACE_USER USER_ENTERED_BACKGROUND/USER_ENTERED_FOREGROUND and analytics `spaceDurationInBackground`; (3) institution admins switch always-on recording on themselves (Settings > Permissions > Recording, plan permitting) and the per-Space opt-out reaches the next call; (4) no boards API and no board deep link (a Space opens on the user's last-viewed board, else the first); on Pencil's roadmap; (5) retries: 10 attempts over about an hour, order not guaranteed; (6) a Space link cannot carry a board id; (7) iframe: no frame-ancestors / X-Frame-Options, fresh token per page load — Safari/ITP and Chrome with third-party cookies blocked still need our own empirical test.

HELPDESK FACTS (helpdesk.pencilspaces.com, read 2026-10-15):
- Recording modes (institution-wide, Settings > Permissions > Recording; support 2026-10-16: institution admins can choose Always-on themselves if the plan includes always-on cloud recording): Always-on (every call in every Space auto-recorded, hosts cannot stop/pause; applies at once to NEW Spaces, up to 3 h for Spaces with recent calls — this 3 h is about switching the INSTITUTION mode; the per-Space disableAlwaysOnRecording takes effect from the next call), Host recording (hosts start/stop), Disabled. Options: prevent local recording; "Record participant video" toggle — turn OFF to exclude student video from cloud recordings (privacy for minors); who may download/delete; recordings admin-only or shareable; default recording access. Cloud recordings capture up to 3 h each and include the whiteboard automatically. Cloud recording hours are BILLED separately (only while recording is active); Space usage bills per user-hour once 2+ users are present (plan dependent).
- Transcripts: English only; need audio within the first 30 s (a silent start can prevent a transcript); diarized with speaker names.
- AI Summaries: Expert plan and above; Settings > AI Assist > Session Summaries; generated for all future cloud-recorded sessions; delivered by optional post-session email (admins choose hosts/participants, invited vs present) and in the Recordings dashboard; exposed via GET /transcriptions/{recordingId}.summary.
- AI Coach ("Coaching Insights"): Advanced plan and above; Settings > AI Assist > Coaching Insights; POST-SESSION only: requires cloud recording processed + transcript with speaker names + AI processing; for a 1 h session the helpdesk says transcription takes ~25 min and analysis 2-5 min, so insights land ~30 min after the session (support 2026-10-16 gives fresher figures: transcript ~10 min, summary and AI Coach ~15 min); four CMU-grounded dimensions (Communication, Engagement, Content Accuracy, Instructional Clarity) with per-moment playback and talk-time balance; rubrics customizable per institution via Pencil; insights generated only for HOSTS; visible to admins and hosts, never to students; exposed via GET /analytics/sessions/{sessionId}/reports. Post-session emails configurable under Settings > AI Assist > Post-Session Emails (we should disable emails to API users or route them to our own notifications).
- LIVE in-session signals Pencil offers: the helpdesk lists private host alerts for a student going idle or switching tabs, Observer Mode for admins, safeguarding/nudity-detection alerts. Support 2026-10-16 names one live host notification only — no separate idle alert: "distraction notifications", shown when a participant switches away from the Pencil tab, hidden in Spaces with 5 or more participants, switchable off under Settings > AI Assist > In Session, and not exposed by the API — the signals are SPACE_USER USER_ENTERED_BACKGROUND / USER_ENTERED_FOREGROUND webhooks and the per-user `spaceDurationInBackground` (admins/hosts). There is NO live teacher-coaching nudge feature (confirmed by support); AI Coach is post-session.
- Attendance (plan-gated; needs an Event linked to the Space): users joining within 10 min of event start are auto-marked Present, later = Late, never = Absent; hosts can override during the event; after the event only admins can edit; CSV export under Analytics > Attendance.
- "End Event" flow (Settings > Feedback): at the event's end time the call auto-disconnects and hosts/participants are redirected to configured URLs (with attribution of Space/user/event) — usable to bounce users back to OUR app after a lesson if we mirror sessions as Events; 5-minute warning notification; hosts may extend events (configurable).
- Safeguarding alerts and nudity detection are separate opt-in features (helpdesk articles 15960073, 15005606); AI snippets (16543197) exist too.
